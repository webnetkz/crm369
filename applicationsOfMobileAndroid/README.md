# CRM369 для Android

Нативное приложение CRM369 на Kotlin и Jetpack Compose. Одна сборка работает с любым порталом:
как в Битрикс24, пользователь вводит адрес домена, на котором развернута CRM, приложение
проверяет портал и выполняет вход. На одном устройстве можно держать несколько порталов и
переключаться между ними.

- Пакет: `com.appswebnetkz.crm369.android`, версия `3.0.0` (код `3`).
- Android 8.0+ (minSdk 26), targetSdk / compileSdk 36.
- Языки интерфейса: русский (по умолчанию) и английский, выбор в настройках приложения.

## Требования

- Android Studio с поддержкой AGP 8.10 (Meerkat Feature Drop / Narwhal или новее).
- JDK 17 или новее (подходит встроенный в Android Studio JBR).
- Android SDK Platform 36 (Android Studio предложит установить при синхронизации).
- Сервер CRM369 с мобильным API `/api/mobile/v1` из этой ветки (эндпоинты `portal`,
  `bootstrap`, `web-session` и модульные API).

## Сборка

1. Откройте папку `applicationsOfMobileAndroid` в Android Studio (**File → Open**) и дождитесь
   синхронизации Gradle. Gradle Wrapper (8.14.3) уже в репозитории.
2. Debug-сборка: кнопка **Run** или
   ```bash
   ./gradlew assembleDebug
   ```
   APK: `app/build/outputs/apk/debug/app-debug.apk`.
3. Unit-тесты (JVM, без эмулятора):
   ```bash
   ./gradlew testDebugUnitTest
   ```
4. Release-сборка с подписью:
   - создайте keystore (**Build → Generate Signed Bundle / APK** или `keytool`);
   - скопируйте `keystore.properties.example` в `keystore.properties` и укажите путь к
     keystore, alias и пароли. Файл и `*.jks` не попадают в Git (`.gitignore`);
   - выполните
     ```bash
     ./gradlew assembleRelease   # APK: app/build/outputs/apk/release/app-release.apk
     ./gradlew bundleRelease     # AAB для Google Play
     ```
   Без `keystore.properties` release-APK собирается неподписанным.

## Подключение к порталу

На первом экране вводится адрес портала: `crm.company.kz`, `https://crm.company.kz` или адрес с
путем — путь отбрасывается. Поддерживаются кириллические домены (переводятся в punycode) и
нестандартные порты. Приложение запрашивает `GET /api/mobile/v1/portal`, проверяет, что это
CRM369 с совместимой версией API, показывает название и логотип портала и переходит ко входу.

- Вход: email и пароль, затем при необходимости код двухфакторной аутентификации или код
  восстановления. Токен (`crm369_mobile_…`) хранится в зашифрованном виде (AES-GCM, ключ в
  Android Keystore) и не попадает в резервные копии.
- Bearer-токен отправляется только на домен портала, к которому он выдан.
- Несколько порталов: **Меню → Сменить портал** или **Профиль → Мои порталы**.
- Если сервер требует подтвердить email или включить 2FA, приложение предлагает открыть портал
  в браузере.

Release-сборка работает только по HTTPS. Для локальной разработки HTTP разрешен для
`localhost`, `127.0.0.1` и адреса хоста из эмулятора `10.0.2.2` (например,
`http://10.0.2.2:8000`), а debug-сборка разрешает HTTP для любых адресов (например, для сервера
разработки в локальной сети) и доверяет пользовательским сертификатам.

## Push-уведомления (Firebase из конфигурации сервера)

В приложении нет `google-services.json`: параметры Firebase приходят с портала, поэтому один APK
работает с любым порталом, а у каждого портала может быть свой Firebase-проект.

Настройка на сервере:

1. В Firebase Console создайте проект (или используйте существующий) и сервисный аккаунт с
   ролью отправки сообщений. Укажите в `.env` `FCM_PROJECT_ID` и путь к JSON-ключу
   `FCM_SERVICE_ACCOUNT_PATH` (файл ключа храните вне репозитория).
2. Добавьте в этот проект Android-приложение с пакетом `com.appswebnetkz.crm369.android`.
   Из выданного `google-services.json` перенесите публичные параметры клиента:
   - `client[].client_info.mobilesdk_app_id` → `FCM_ANDROID_APP_ID`;
   - `client[].api_key[].current_key` → `FCM_ANDROID_API_KEY`;
   - `project_info.project_number` → `FCM_SENDER_ID`.
3. Обновите кэш конфигурации: `php artisan config:cache`.

Приложение получает эти параметры из `GET /api/mobile/v1/portal` и `GET /api/mobile/v1/bootstrap`,
инициализирует Firebase во время работы и регистрирует токен устройства через
`PUT /api/mobile/v1/device` (при выходе — `DELETE /api/mobile/v1/device`). Уведомления приходят в
канал «Обновления CRM» (`crm369_updates`); нажатие открывает нужный экран по `action_path`, а если
уведомление относится к другому порталу — сначала переключает портал. На Android 13+ приложение
один раз запрашивает разрешение на уведомления.

## Веб-интерфейс внутри приложения

Разделы, которые остаются в веб-версии (настройки администратора, комната видеоконференции на WebRTC,
публичные страницы, диаграмма Ганта, CSV-обмен задач и оборудования), открываются во встроенном
браузере без повторного входа:
приложение вызывает `POST /api/mobile/v1/web-session` и получает одноразовую ссылку
`/mobile/web-session/{token}` (действует 60 секунд), которая создает веб-сессию в WebView.
Во встроенном браузере работают загрузка файлов, камера и микрофон (по разрешению Android) и
скачивание через системный менеджер загрузок (на Android 10+ — в папку «Загрузки»). **Меню → Полная версия портала** открывает весь веб-интерфейс.

## Архитектура

```
app/src/main/java/com/appswebnetkz/crm369/
├── AppContainer.kt, Crm369Application.kt, MainActivity.kt   — ручной DI, Coil, единственная Activity
├── core/
│   ├── json/        — чтение ответов API через kotlinx JsonElement (без плагина сериализации)
│   ├── network/     — ApiClient (OkHttp, bearer, язык, multipart, скачивание), ApiException
│   ├── portal/      — нормализация адреса (DomainNormalizer), проверка портала (PortalDiscovery)
│   ├── session/     — аккаунты порталов, зашифрованное хранилище, bootstrap, SessionManager
│   ├── push/        — Firebase из конфигурации сервера, каналы и показ уведомлений
│   ├── links/       — DeepLinkRouter: веб-пути CRM → экраны приложения
│   ├── files/, scan/, settings/, util/
├── ui/
│   ├── theme/       — тема (бренд #0A6C74, светлая/темная), AppIcons — единственный источник иконок
│   ├── components/  — каркасы экранов, состояния, строки, диалоги, Loadable/PagedLoadable
│   ├── form/        — декларативные формы (FieldSpec, FormState, FormScreen)
│   ├── navigation/  — маршруты, AppNavigator, реестр модулей и разделов администрирования
│   ├── onboarding/  — адрес портала, вход, список порталов
│   ├── main/        — вкладки «Главная», «Чаты», «Задачи», «CRM», «Меню»
│   ├── notifications/, profile/, web/
└── feature/<module>/ — модули CRM: маршруты <Name>Routes, граф <name>Graph(), экраны, репозиторий
```

Видимость модулей и пунктов администрирования определяется правами из `bootstrap.abilities`,
включенными модулями портала и личными настройками меню (скрытые пункты, порядок, собственные
ссылки) — так же, как в веб-версии. Функции без нативного экрана открываются во встроенном
браузере, поэтому все возможности портала доступны из приложения.

### Как добавить или доработать модуль

- Код модуля — в `feature/<name>/`: объект `<Name>Routes` (константы маршрутов и функции-строители),
  `fun NavGraphBuilder.<name>Graph()`, экраны и репозиторий поверх `ApiClient`.
- Строки — в `res/values/strings_<name>.xml` (русский) и `res/values-en/strings_<name>.xml`
  (английский) с префиксом `<name>_`; набор ключей в обоих файлах одинаковый.
- Иконки — только через `AppIcons`.
- Образец полного модуля — `feature/contacts` (список с поиском и фильтрами, карточка, форма с
  аватаром, комментарии).

## Первая сборка

Проект написан без доступа к Android SDK и репозиториям Google Maven, поэтому первая компиляция
выполняется в Android Studio. Код проверен статически (синтаксис, импорты, вызовы, ресурсы,
маршруты), а модели и репозитории модулей скомпилированы компилятором Kotlin. Если сборка покажет
ошибку, пришлите лог `Build` — исправление обычно точечное. Версии зависимостей задаются в
`gradle/libs.versions.toml`; при необходимости Android Studio предложит их обновить.

## Безопасность

- Токены зашифрованы ключом Android Keystore; `allowBackup=false`, данные исключены из облачных
  копий и переноса на другое устройство.
- В логах debug-сборки заголовок `Authorization` скрыт; release-сборка не пишет HTTP-логи.
- В репозитории нет секретов: `keystore.properties`, `*.jks`, `*.keystore`, `firebase.properties`
  исключены через `.gitignore`.
